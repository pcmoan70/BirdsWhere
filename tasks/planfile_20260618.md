# Speed & Robustness Improvement Plan — 2026-06-18

A staff-level review of the in-browser BirdNET explorer (`docs/`), focused on
**performance** and **robustness**. Findings come from a three-track review
(perf / robustness / data-layer); the headline robustness items were spot-checked
against the live code (line refs verified). Items are prioritised by
impact-per-effort, not by where they were found.

Ground rules for execution (per `CLAUDE.md`):
- Vanilla ES5-style JS, no new deps/build tooling, surgical changes.
- Any user-visible change → bump `VERSION` in `docs/sw.js`, update Help/`README.md`, log to `CHANGES.md`.
- Land in small, independently-verifiable commits; each phase below is a commit boundary.

---

## Phase 1 — Correctness bugs (do first; small, high-value) — ✅ DONE 2026-06-18 (sw v461)

These are real defects (verified), not just optimisations. Low LOC, high payoff.
All five landed; `node --check` clean. See `CHANGES.md`.

- [x] **1.1 Failed/timed-out sightings fetches are cached permanently** *(HIGH, verified)*
  `app.js:1909` (`allSightingsCache[ck] = pr`) and `app.js:1937` (`histSightingsCache[ck] = pr`)
  store the *promise* unconditionally. A transient eBird 401, a GBIF timeout, or any
  rejection becomes the permanent answer for that location until a global cache wipe
  (a settings change). Two independent reviewers flagged this.
  **Fix:** after resolution, if `out.failed.length || out.timedOut.length`, delete the
  cache entry so the next click re-fetches; also `pr.catch(function(){ delete cache[ck]; })`
  to drop rejected promises. Keep the in-flight promise to dedup concurrent clicks.

- [x] **1.2 Worker death hangs every pending inference forever** *(HIGH, verified)*
  `app.js:3280` — `worker.onerror` only `console.error`s. On a wasm OOM/abort the
  `infer` reply never arrives, so promises in `pendingInferences` never settle and the
  computing overlay spins forever.
  **Fix:** in `worker.onerror`, reject + clear all `pendingInferences` entries (surface a
  user-visible error); optionally recreate the worker. Add a per-inference timeout that
  rejects the pending promise as a backstop.

- [x] **1.3 `runInference` unguarded against a null/dead worker** *(HIGH, verified)*
  `app.js:7855` — `worker.postMessage(msg, [buf])` has no null check / try-catch; if
  `initWorker` failed or the worker was terminated this throws inside the Promise
  executor instead of rejecting cleanly.
  **Fix:** `if (!worker) { reject(new Error("worker unavailable")); return; }` and wrap
  `postMessage` in try/catch → `reject`.

- [x] **1.4 Drive-sync trip writes to IndexedDB are fire-and-forget** *(HIGH)*
  `app.js:2344-2346` (`applyRemote`) — `AppIDB.put(...)`/`.del(...)` are not awaited and
  have no `.catch`; on quota/abort the merged trip is dropped from durable storage while
  in-memory state claims success (silent data loss + unhandled rejection).
  **Fix:** attach `.then(null, fn)` and surface `t("err.storageFull")` as `persistDetSet`
  already does (`app.js:5226`).

- [x] **1.5 `AppIDB.open()` caches a rejected promise forever** *(LOW)*
  `idb.js:20-35` — a first-open failure (blocked/private mode) poisons all later
  `get/put/del`. Boot hydration falls back to localStorage, but runtime `put`s keep
  failing silently.
  **Fix:** null out `dbPromise` on rejection so a later call retries `open()`.

## Phase 2 — Rendering performance (biggest perceived speed wins)

The map repaint path is the dominant main-thread cost on pan/zoom and during sweeps.
**2.1 + 2.3 landed 2026-06-19 (sw v464); `node --check` clean.** Together they remove
most of the redundant projection cost (paints coalesce to one/frame, and the cell list
is computed once/frame), which shrinks 2.2's marginal benefit — 2.2 deferred pending
on-device visual verification (alignment risk, can't profile headless here).

- [x] **2.1 Coalesce overlay repaints with `requestAnimationFrame`** *(HIGH)* — DONE
  Added `schedulePaint()` (rAF-coalesced, no-ops if already queued); `paintOverlay()`
  cancels a pending frame so the final synchronous paint still completes before
  `updateLegend`. Wired into the `moveend` handler and both sweep loops' intermediate
  per-chunk/per-week repaints; the guaranteed final paint stays synchronous.

- [ ] **2.2 Cache projected hex vertices by `(cell, zoom)`** *(HIGH, DEFERRED)*
  `paintRangeH3`/`paintOverlayH3` call `latLngToContainerPoint` 6× per hex on every
  repaint. Pan-independent absolute pixels come from `map.project(latlng, zoom)`; at
  paint time subtract `map.getPixelBounds().min` for container coords.
  **Risk:** getting the origin transform wrong misaligns the overlay; needs a real
  browser to verify. Do this with the user watching, after 2.1/2.3 are confirmed good.

- [x] **2.3 Compute `h3CellsInView()` once per render, not 2–3×** *(HIGH)* — DONE
  Memoised by `(res, zoom, viewport, center)`; repeat calls within a render/frame reuse
  the result. Verified no caller mutates the returned array (read-only iteration).

- [ ] **2.4 Single-pass normalisation + max-finding over the grid** *(MEDIUM)*
  `normalizeProbs`/`perceptualNorm` (`app.js:424-431, 8191-8203`) plus repeated explicit
  max loops in `renderRichness` (`8357, 8396, 8403`) and `showCachedWeek` (`8309`) each do
  a separate full pass and a fresh `Float32Array`.
  **Fix:** fold max-finding into one pass; reuse the buffer when grid size is unchanged.

- [ ] **2.5 Quantised `rgba` palette instead of per-hex string build** *(LOW)*
  `app.js:7983, 8060` build a fresh `rgba(...)` string per hex per repaint.
  **Fix:** precompute ~64 alpha-bucketed `rgba` strings and index in.

- [ ] **2.6 Integer-keyed cell maps instead of `"lat,lon"` strings** *(LOW)*
  `app.js:8154, 8166-8189, 10368-10374` build string cell IDs per cell.
  **Fix:** key by packed int `latIdx * nLon + lonIdx` when grid geometry is known.

## Phase 3 — Inference & list performance

- [x] **3.1 Skip masked species in the richness worker loop** *(HIGH)* — DONE 2026-06-19 (sw v465)
  `inference-worker.js` now precomputes the in-group species indices once per request and
  each cell counts only those instead of walking all ~12,012 species. Behaviour-preserving
  (equivalence-tested vs the old loop: no-mask / full / random / empty masks, 200 trials).

- [ ] **3.2 Cache `speciesName(label)` per render** *(MEDIUM)*
  `app.js:10150-10210` — `speciesName`→`nameInCol` (object lookups + `toLowerCase`) runs
  3–4× per species across `buildResults`, `nameLinkHtml`, the CSV loop, and the PDF
  snapshot loop. The lang/taxCol pair is stable per render.
  **Fix:** memoise resolved names for the current render pass.

- [ ] **3.3 Per-group index arrays for the species list** *(MEDIUM)*
  `app.js:10152` loops all 12,012 labels even when filtered to a small group.
  **Fix:** precompute per-class index arrays (leverage existing `labelClass`) and iterate
  only group members.

- [ ] **3.4 Cache `groupMask()` per group** *(LOW)*
  `app.js:7866-7871` allocates a fresh `Uint8Array(~12k)` every richness render.
  **Fix:** cache per `speciesGroup`, invalidate on group change.

- [ ] **3.5 Sort species list off a key array, not the DOM** *(LOW)*
  `app.js:795-815` reads sort keys via `getAttribute`/`textContent`/`querySelector`
  inside the comparator (O(n log n) DOM queries).
  **Fix:** extract keys to a plain array once, sort, then reorder nodes.

- [ ] **3.6 Reuse a single sorted cohort in analysis views** *(MEDIUM)*
  `analysis.js:221-222, 298` sort the cohort up to 3× (`topArr`, `topProb`, table); the
  prob min/max double-loops 48×N.
  **Fix:** compute `arrival`/`probability` once, reuse one sorted copy, fold global
  min/max into `computeVisibleSpecies`.

## Phase 4 — Data-layer robustness & efficiency

- [x] **4.1 Surface iNat/Artsobs failures instead of swallowing them** *(HIGH)* — DONE 2026-06-19 (sw v466)
  iNat and Artsobs (plus Artportalen) now propagate a first-page / probe failure so
  `guardFetch` flags the source; later-page failures still keep partial results. Completes
  the Phase 1.1 dependency (flagged failures now evict the location cache).
  Original problem below:
  `fetch.js:226-227` (`fetchInatAll` `try/catch`→`break`) and `fetch.js:305`
  (`fetchArtsobsAll` maps rejection→`{}`). A 500/429 reads as "0 results" — the user
  can't tell "no birds here" from "source is down", and 1.1 then locks in the empty answer.
  **Fix:** let page-1 errors propagate (mirror Laji's `if (p === 1) throw`) so `guardFetch`
  flags the source red.

- [x] **4.2 Shared retry/backoff for the direct sources** *(HIGH)* — DONE 2026-06-19 (sw v466)
  Extracted `fetchRetry(url, opts, extSignal)` (per-request 25s timeout + 429/5xx/network
  backoff, `Retry-After` aware, 5 attempts) and routed ALL six adapters through it,
  including `gbifPage` (now a thin JSON wrapper). One retry implementation, no duplication.
  Control flow unit-checked (OK / 4xx / 429-then-OK / persistent 5xx / network / aborted).

- [x] **4.3 Dedup across sources when observer is blank** *(MEDIUM)*
  `aggregate.js:156, 162` — `nativeKeys` only populates for records with `r.observer`, so
  an observation arriving via both a national source and the GBIF republish is
  double-counted whenever `recordedBy`/observer is empty (common for eBird geo/recent).
  **Fix:** fall back to a `species + rounded loc + date + count` key for the no-observer
  case (accept a small false-merge risk).

- [ ] **4.4 Parallelise `fetchGbifHistoric` recursive halves** *(MEDIUM)*
  `fetch.js:209-211` — bisected sub-ranges are awaited sequentially, so a dense 90-day
  window becomes a long serial chain of 4-wide bursts.
  **Fix:** run the two disjoint halves with `Promise.all`; cap total concurrency with a
  shared semaphore instead of re-entering serially.

- [ ] **4.5 Flag truncated results for Artportalen/Laji** *(MEDIUM)*
  `fetch.js:334` (1800 cap) / `fetch.js:367` (6000 cap) silently stop at a fixed page cap.
  **Fix:** detect a full last page and flag the source as "truncated" in the loading line;
  ideally date-slice like Artsobs.

- [x] **4.6 Clamp iNat radius to 200 km** *(LOW)*
  `fetch.js:218` passes `radius=rkm` raw; iNat silently caps at 200 km, diverging from the
  other (clamped/bbox) sources. **Fix:** `Math.min(200, rkm)`.

- [ ] **4.7 Move eBird observer enrichment off the source timeout budget** *(LOW)*
  `fetch.js:251-280` — up to 150 checklist lookups run inside the per-source abort timer
  (`app.js:1889`), so a busy hotspot trips a false `timedOut` even though observations
  arrived (names are cosmetic). **Fix:** enrich under a separate, shorter budget or after
  the source is marked done.

## Phase 5 — Service worker & sync correctness

- [x] **5.1 Protect the computed H3 range blob from the tile LRU** *(MEDIUM)*
  `sw.js:234-295` trims the shared `map-pool` by insertion order; the app's range blob
  (`app.js:551-565`, `H3_POOL_URL`) is treated as an ordinary LRU entry and can be evicted
  (losing the user's computed range), and the two writers race.
  **Fix:** give the range blob its own version-independent cache, or have `trim()` skip the
  `H3_POOL_URL` key.

- [x] **5.2 Serialize or drop the LRU re-stamp** *(MEDIUM)*
  `sw.js:236-240` — `delete(req).then(put(req,...))` runs detached; a concurrent request or
  `trim()` reading `keys()` mid-delete can lose the entry or double-fetch.
  **Fix:** serialize re-stamps the way `queueTrim` serializes trims, or accept pure FIFO
  (lower correctness cost than the race).

- [~] **5.3 Don't cache opaque error tiles** *(MEDIUM)* — KEPT opaque caching (every tile is opaque; not caching would break offline). Visible errors already uncached. Documented; see CHANGES sw v467.
  `sw.js:242-249` caches `res.type === "opaque"` (status 0); an opaque 404/500 is served
  forever as a broken tile.
  **Fix:** skip caching opaque responses (or exclude from the persistent set / revalidate).

- [x] **5.4 Navigation fallback when offline & uncached** *(MEDIUM)*
  `sw.js:197-214` — `networkFirst` can resolve `cache.match(req)` to `undefined`, and
  `respondWith(undefined)` yields a hard network error (blank page) instead of the shell.
  **Fix:** for navigation requests fall back to cached `index.html`/`./`; never respond
  `undefined` — synthesize an error Response.

- [x] **5.5 Drive `findFile`: exclude trashed, pick newest** *(MEDIUM)*
  `gdrive-sync.js:148-154` — query lacks `trashed=false` and blindly takes `files[0]`;
  duplicate app-data files (concurrent two-device creation) cause overwrite ping-pong.
  **Fix:** add `and trashed=false`, sort by `modifiedTime` desc, pick newest.

- [x] **5.6 Define merge behaviour for missing/equal `updatedAt`** *(MEDIUM)*
  `gdrive-sync.js:205-206` — `incomingWins = remoteStamp > bootUpdatedAt() && !localDirty`;
  a remote with missing/equal stamp makes local always win, so genuine remote scalar
  settings never propagate. **Fix:** handle missing/equal stamps explicitly (content tie-
  break) and document that every payload must carry `updatedAt`.

- [x] **5.7 Resync `state.js` cache on total quota-trim failure** *(LOW)*
  `state.js:62-71` — on all-attempts-fail, in-memory `cache` holds untrimmed data that was
  never persisted, so readers see phantom data lost on reload.
  **Fix:** on total failure re-read localStorage to resync `cache` (or make callers consult
  `lastSaveOk()`).

## Suggested execution order

1. **Phase 1** (correctness, ~half a day) — ship first; each item is a few lines and fixes
   a real user-facing failure.
2. **Phase 2** (rendering) — the biggest *felt* speed improvement; 2.1–2.3 together.
3. **Phase 3.1** (worker mask) — cheap, large win for richness in a single group.
4. **Phase 4** then **Phase 5** — resilience hardening; lower visibility but they prevent
   silent wrong answers and offline breakage.

## Verification

No test harness exists. Verify each phase by:
- Serving locally (`cd docs && python -m http.server 8000`) and exercising the affected
  path (pan/zoom for Phase 2, a known-busy hotspot for Phase 3/4, DevTools offline +
  throttling for Phase 5, killing the worker via DevTools for 1.2).
- Phase 2/3: profile a pan and a sweep in DevTools Performance before/after; record the
  main-thread time delta in `CHANGES.md`.
- Phase 4: temporarily point a source at a 429/500 (or block it in DevTools) and confirm it
  shows red/failed rather than "0".
- When the user confirms a fix is good, freeze the behaviour where practical.

> Sequencing note: **Phase 1.1 depends on Phase 4.1** — until iNat/Artsobs failures are
> surfaced (not swallowed), the cache-eviction-on-failure fix can't see them. Either land
> 4.1 first, or do 1.1 + 4.1 together.
